三、模型档案 每个神经网络是什么

FLUX.2 klein 4B

Black Forest Labs · Apache 2.0 · 主力出图模型

类型
扩散模型（rectified flow transformer），文生图和参考图编辑一体
规模
4B 参数，蒸馏版只需 4 步去噪
文件
flux-2-klein-4b.safetensors bf16，7.75GB
搭档
Qwen3-4B 文本编码器 + FLUX.2 VAE
引擎
ComfyUI（PyTorch MPS）

提示词 [+ 参考图] → 768×1344 剧照

坑：模板默认的 fp8 版本在 Mac 上直接报错，必须用 bf16。

Qwen3-4B（文本编码器）

阿里通义 · klein 的"耳朵"

类型
语言模型，这里只用它把提示词编码成向量，不生成文字
文件
qwen_3_4b.safetensors，约 7.5GB
位置
text_encoders/

英文提示词 → 条件向量（conditioning）

FLUX.2 VAE

Black Forest Labs · 图片和"潜空间"之间的翻译

类型
变分自编码器：编码器把图压进潜空间，解码器还原成图
文件
flux2-vae.safetensors，约 0.3GB
用途
编辑模式下先编码参考图（ReferenceLatent），最后解码结果

像素 ⇄ 潜空间

坑：MOSS 用的 flux2-vae_small 是精简版，不要和 klein 混用。

gemma-4-e4b

Google DeepMind · 能看图的语言模型

类型
多模态大语言模型：视觉编码器 + 语言模型
规模
7.9B 参数，运行开销约等于 4B（effective 4B）
文件
6.86GB
两份工作
拆分镜（读剧本）、看图质检（打分、找瑕疵、判断表情）
引擎
LM Studio，OpenAI 兼容接口，空闲 300 秒自动卸载

文字 [+ 图片] → JSON（按 Schema 约束）

局限：不让它判断"是不是同一个人"，输出不稳定、小模型分辨力弱。

YuNet

南方科技大学于仕琪团队 · MIT · 人脸检测

类型
轻量卷积网络（CNN）
文件
face_detection_yunet_2023mar.onnx，约 230KB
输出
每张脸 15 个数：框、5 个关键点（双眼、鼻尖、嘴角）、置信度
额外用途
用关键点估算脸的转向（yaw）和大小，写进报告

整张图 → 人脸框 + 关键点

SFace

OpenCV Zoo · Apache 2.0 · 人脸识别

类型
人脸识别网络，度量学习训练（同一人靠近、不同人推远）
文件
face_recognition_sface_2021dec.onnx，约 37MB
输出
128 维特征向量，两两算余弦相似度
阈值
官方 0.363（真人照片）→ 自测 0.40（klein 生成的脸）

摆正的 112×112 人脸 → 128 个数字

局限：小脸、侧脸、极端表情会压低分数；大笑闭眼时和人眼判断不一致。

Qwen3-TTS 1.7B CustomVoice

阿里通义 · 语音合成

类型
文本转语音模型，内置多个中文音色，支持自然语言语气指令
音色
Vivian、Serena、Uncle_Fu（旁白）、Eric（四川话）、Dylan（北京话）
引擎
mlx-audio（MLX，苹果芯片原生）

台词 + 音色 + "紧张，压低声音" → wav

Whisper large-v3-turbo

OpenAI · 语音识别 · 旁路工具

类型
编码器-解码器 Transformer，语音转文字
文件
约 1.6GB（国内经 hf-mirror 下载）
引擎
mlx-whisper
为什么不进流水线
流水线的台词已知，按配音时长直接算字幕更准更快

视频语音 → srt（加初始提示避免繁体）

MOSS-Image 5B（已退役）

OpenMOSS · 阶段一的文生图模型

类型
扩散模型（单流 DiT），支持画框布局控制
文件
int8 主模型 + Qwen3.5-9B（GPTQ W4A8）文本编码器 + flux2-vae_small
速度
25 步 × 8.5 秒 ≈ 3.9 分钟 / 张
退役原因
纯文字描述锁不住长相，跨镜头一致性只有 0.26

坑：提示词扩写（9B GPTQ）8 分钟只走 2%；9:16 取整成 768×1360 会算出 NaN 黑图。

四、Mac 上的模型格式 同一个模型，格式决定能不能跑

格式为谁优化在 M5 Pro 上遇到的地方
bf16通用✅ 原生支持klein 4B、Qwen3-4B
MLX 4/8bit苹果芯片✅ 最快LM Studio 模型、Qwen3-TTS、Whisper
int8 convrotNVIDIA⚠️ 能跑但慢MOSS-Image 主模型
GPTQ W4A8NVIDIA❌ 慢到不可用MOSS 的 9B 文本编码器
fp8 e4m3fn新款 NVIDIA❌ MPS 直接报错klein 模板默认文件

经验：Mac 上优先选 bf16 或 MLX 格式；文件名里带 fp8、gptq、int8 的先打个问号。

五、几个关键设计 为什么这么分工

  • 专用引擎 + 统一编排：语言模型放 LM Studio、扩散模型放 ComfyUI、语音放 MLX；同一个 9B 语言模型放进 ComfyUI 跑，8 分钟只走 2%。
  • 认脸用 SFace，不用大模型：输出确定、可量化、毫秒级；大模型留给"画面对不对、表情怎样"这类需要理解的判断。
  • 能挑不能造：换 seed 重画只能在随机结果里挑，参考图生成才能锁住长相（0.26 → 0.58）。
  • 定妆照和剧照同一个模型：风格统一后分数整体上升。
  • 人眼是最终标准：阈值用人工标注 + 对照组校准，官方 0.363 只是起点。
  • 24G 轮流用：出图、看图、配音三个大模型不同时常驻，每一步结束主动释放。
