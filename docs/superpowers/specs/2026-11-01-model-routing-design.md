# 模型路由设计

用户已批准最小改动方案：本地优先，云端兜底，目前只有本地模型。

保留 `chat(cfg, messages, schema, ...)` 和 `[lmstudio]`；新增可选的 `[lmstudio.cloud]`，默认 `enabled = false`。云端启用后以环境变量提供密钥，分别配置文本 `model` 与多模态 `vision_model`；没有配置看图模型时绝不向纯文本云端发送图片。每次先本地，连接失败、超时、HTTP 错误、响应结构错误、空输出、JSON 或 schema 校验失败后最多调用一次云端。取消操作不触发兜底。

本地和云端分别设置超时。本地保留 ttl；云端仅发送通用 Chat Completions 参数并用 Bearer 鉴权。使用 jsonschema 校验结构化输出；项目 schema 补全 additionalProperties=false 以兼容严格输出。错误和路由日志不包含密钥、剧本、图片或原始响应正文。两端失败报告各自失败类别。

质检在本地不可用且云端看图已就绪时保留看图路径；环境检查显示云端配置是否完整，但不做付费探测。CLI、网页沿用同一调用入口。未配置云端时维持本地运行与质检降级行为。

方案比较：直接扩展现有 urllib 客户端改动最小，用户已选；引入路由框架方便更多供应商，但当前增加依赖和迁移成本。仅新增 jsonschema 用于可靠校验，无供应商 SDK。不涉及图像生成、视频生成、配音、发布机器人或真实云端调用。

验证使用 unittest 模拟 HTTP 边界，覆盖本地成功、各种失败兜底、默认关闭、缺少密钥、两端失败、云端模型选择、鉴权及 TTL 分离、质检集成。真实云端需用户后续配置后验证。
